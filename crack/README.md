# Synthetic password-storage exercises

These scripts use six **invented classroom accounts** embedded in `make_dump.py`. They never connect to NotesApp, import a real user dump, or guess passwords against a service. The 170-entry bundled wordlist is a teaching fixture; no external provenance is asserted.

From the repository root, use Python 3.11+ and an isolated environment:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r session03/requirements.txt
.venv/bin/python crack/make_dump.py
.venv/bin/python crack/crack.py
.venv/bin/python crack/benchmark.py
```

Default paths are resolved relative to each script, so the commands also work when called by absolute path from another directory. Generated files stay in the ignored `crack/results/` directory. Keep old `leaked_users.txt`, historical result JSON, and private reports out of the commit.

The MD5 demonstration accepts only the exact synthetic fixture generated by `make_dump.py`. It tries each candidate once and records which fixture passwords appear in this particular wordlist. An unrecovered password is **not** proof that it is secure. Optional `--dump`, `--wordlist`, and `--output` arguments accept paths; input limits keep this demonstration bounded at 10,000 candidates.

The benchmark performs exactly 10,000 MD5 digest operations, one Argon2id hash, and one verification on a fixed invented string. Argon2id uses 64 MiB, three iterations, and four lanes, matching the application's configured hasher. No long-running search is performed. Wall-clock and process CPU times are recorded separately; CPU time can exceed wall-clock time when native work uses multiple threads.

These outputs are **new measurements**, not a reconstruction of the previously submitted Lab 2 report. No unrecorded prior prediction, timing, or account count is filled in. A single sample depends on hardware and load, uses different operation counts for the two algorithms, and is not an estimate of an attacker's speed.
